## State and boundary

One immutable reducer is the authority across all pages. Source identity, session generation, connection, media arrival, preview pipeline and telemetry freshness are separate fields. Program commit and downstream observation are separate. A command is correlated by run epoch and command ID; recovery media events additionally require the current session generation. Repeated Take while pending is ignored. Navigation clears arming only. Reset discards the queue and invalidates old events. Transition stages are explicit rather than simulated via optimistic state mutation.

`simulatedApi` is a closed in-process adapter accepting only POST /sim/action. Unknown requests throw; it contains no fetch or network fallback. MSW was considered but adds a service-worker lifecycle for no benefit when this first slice needs no HTTP requests. A reducer suffices; a state-machine dependency and Storybook were not added. UI tests exercise the same reducer through React interactions. Native buttons/select/links preserve keyboard semantics; source choices have pressed state, evidence labels do not rely on color alone, and command controls keep stable positions.

English headings and shared copy live in `copy.ts`; domain IDs remain stable. Remaining component-specific sentences are English and require catalog extraction before a second locale. No completed localization or screen-reader conformance claim.

Manual replay is deliberate and clearly described in the simulator panel. It is not representative of production command timing. Production API, authorization, durable command reconciliation, media observations and any automatic playback scheduler remain separate future decisions.
